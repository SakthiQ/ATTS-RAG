ATTS-RAG: Threat Gate + Trust Gate + Claim Check, on one laptop

A document question-answering system that screens every question, decides which passages the model may read, and releases only the sentences the documents support. Every model runs locally; nothing leaves the machine.

SQ
SakthiQ
November 21, 2026 | 8 min read

Today we are publishing ATTS-RAG, short for Adaptive Threat and Trust Security for retrieval-augmented generation. You upload PDFs, Word files or notes, ask questions, and get answers that cite their sources. Around that ordinary loop sit three security layers.

On a blind test set of 7,517 texts the first layer catches 89.6% of prompt-injection attacks while flagging 2.1% of honest messages. Against 64 poisoned documents the full stack cuts attack success from 23.4% to 6.2%. And on held-out questions, no answer contained a number the documents never stated. It runs on a laptop CPU with Llama 3 through Ollama, and it costs nothing to run.

    What each layer does

    • Layer 1 reads the question. Regex rules, similarity to known attack phrasings, a multilingual classifier and an authority-claim check each score it. The strongest score decides PASS, FLAG or BLOCK.
    • Retrieval finds candidates. Dense search in Chroma and BM25 keyword search are fused, a cross-encoder reranks them, and only the user's own tenant and clearance level are ever searched.
    • Layer 2 decides what the model may read. Each passage must be authorised, match the hash recorded at upload, carry no planted instructions, and come from a source trusted enough. Personal data is masked.
    • Layer 3 checks the answer. Llama 3 drafts a cited answer; every sentence is then checked against the passages by an NLI model plus number, table and citation rules. Unsupported sentences are dropped, not rewritten.
    • Suspicion ties them together. Each user carries a suspicion score that every layer can raise. A user who keeps probing meets stricter thresholds on the next question; an honest user sees the static system.

    Layer 1: read the question first

    A single embedding of a long message averages a short attack away, so the gate scores each sentence, each pair of neighbouring sentences, and the most suspicious pieces joined back together. That last step catches an attack split into two harmless-looking halves. Text is normalised first: invisible characters are removed, look-alike Cyrillic letters folded, and Base64 decoded when it decodes to readable text.

    Suspicion is what makes a patient attacker expensive. On the held-out multi-turn sessions it halves the attack turns that get through, from 23.8% to 11.9%, without blocking a single extra honest turn. The cost is time: a median of 334 ms per message on a laptop CPU, up to about 1.2 s for very long messages.

    Layer 2: decide which passages the model may read

    Every upload gets a trust tier from its source. Official documents are tier 1, a user's own uploads are tier 2, and anything marked untrusted is a last resort. Trusted passages always come first. An unverified passage that contradicts a trusted one on the same point is withheld, so "refunds within 365 days" in someone's upload never sits next to the handbook's "30 days".

    The gate also refuses to guess. A passage the registry does not know fails the integrity check, missing trust metadata counts as unverified, and a flagged upload counts against the person who uploaded it, not against everyone whose question happens to retrieve it.

    Poisoned documents

    We wrote 64 poisoned documents in 8 attack styles, each aimed at one question and each carrying a marker string. An attack succeeds when the marker shows up in the answer. The generator used a naive prompt that follows instructions in documents, which is the hard case.

    Attack success, 64 poisoned documents (lower is better)

    0%10%20%30%

    From eval/results/poison_large_v2. The full stack keeps 88.0% fact recall on the same questions; telling the model to treat documents as untrusted data does nothing on its own.

    Most of the work is done by trust ordering, not by spotting the attack text. Several styles phrase the injection as polite advice with no instruction wording, and neither the pattern scan nor the LLM judge catches those. Putting official sources first and checking every sentence afterwards still holds most of them back.

    Layer 3: release only what the documents say

    Llama 3 drafts the answer as short sentences, each tagged with the passage it used. A small NLI model then checks every sentence against windows of the evidence, and deterministic rules back it up. Every number must appear in the evidence or inside a stated range. A claim about a table row is checked on the table itself. A citation to the wrong passage is moved to the right one. Headings, lead-ins and the "understood as" line can no longer carry a fact without being checked.

    On RAGTruth, a public benchmark of human-labelled hallucinations, the verifier flags 98.8% of hallucinated answers (932 of 943) without any training on the dataset. It is also strict with clean answers: precision is 38.5%, for an F1 of 55.4 against 78.7 for a Llama-2-13B fine-tuned on RAGTruth itself. For a system that would rather say less than say something wrong, that is the trade we chose.

    What it does not do yet

    • A patient attacker gets through eventually. An attacker who keeps rewording finds an unflagged version of 71.1% of attacks within 20 tries. Suspicion slows them down; it does not stop them.
    • Correct sentences are sometimes dropped. The small NLI model costs about 8 points of fact recall, mostly sentences that explain or infer rather than restate.
    • English first. The search embeddings and the verifier are English models. The Layer 1 classifier is multilingual; the rest of the pipeline is not.
    • Conflict detection is lexical. "A full year" against "365 days" is not seen as a contradiction.
    • PDF tables need drawn lines. Tables laid out by spacing alone are read as plain text, and charts inside text pages are not read at all.

    Run it yourself

    You need Python 3.11 and Ollama with Llama 3 pulled. The first start downloads the embedding, reranking, classifier and verification models; after that it runs offline.

    # Llama 3 for answers (about 4.7 GB)
ollama pull llama3

git clone https://github.com/SakthiQ/ATTS-RAG.git
cd ATTS-RAG
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env

# the first administrator; the password is asked for
python scripts/manage_users.py create --username admin --role super_admin

    Or start everything with Docker:

    docker compose up -d --build
docker compose exec ollama ollama pull llama3

    The app opens at localhost:8501 and the API at localhost:8000. Accounts come with four roles, clearance levels for documents, two-factor log-in and an audit log, and the whole system is covered by 548 automated tests.
